## The most important thing learned

**Three separate bugs this session were invisible for the same reason: the test
fixtures could not exhibit the failure.**

That is not a coincidence, it is a pattern, and it has now caused production
incidents on three consecutive sessions:

| Date | Bug that reached production | Why the fixtures could not catch it |
|---|---|---|
| 2026-07-29 | No production model could render at all (`meshoptDecoderLocation` unset) | Seeded placeholders used **no geometry compression** |
| 2026-07-31 | **Every** production garment tripped a CSP violation on load (`blob:` missing from `connect-src`) | Same reason — found the moment `seed:assets` started using `--meshopt` |
| 2026-07-31 | Artwork on a second UV set decimated with zero protection | Seeded placeholders had **no textures and no UVs at all** |

Adding `--meshopt` to `seed:assets` and putting a printed graphic on the
placeholder tee found the second of those **within minutes**. The fixtures had
been green through all of it — 177 tests passing while the 3D stage could not
work for any real file.

**Rule going forward: if production compresses, seed compressed. If production
prints, seed a print.** A fixture that cannot exhibit the failure mode is not a
fixture; it is a green light wired to nothing.

## Traps that cost real time — do not re-learn these

- **Never run the pipeline on its own output.** Meshopt quantizes vertex
  attributes to integers, and `simplify-textured.ts` explicitly bails to a
  position-only fallback when it sees them. A second pass therefore *silently*
  loses artwork protection and makes the wrong stage look guilty. This trap had
  already burned two sessions; `bisect-artwork.mjs` now refuses to start on a GLB
  whose `asset.generator` is not a CLO export.

- **`PRAGMA foreign_keys=OFF` does nothing on D1.** SQLite ignores it inside a
  transaction and D1 wraps statements in one. `defer_foreign_keys` is the
  documented replacement — but it defers *checks*, not **cascades**, so it would
  not have prevented the 2026-07-29 data loss either. **Ordering is what makes a
  table rebuild safe**: stage or drop the referencing tables first.

- **`prune()` renumbers texCoords.** It calls `shiftTexCoords`, so a material
  sampling a *lone* second UV set gets renumbered down to `TEXCOORD_0` before
  decimation ever sees it. This corrected a claim made earlier in the same
  session — the hazard is a material sampling **two or more** UV sets at once, and
  warning on "any texCoord != 0" would have sent the next person chasing a
  phantom.

- **`chromaSubsampling` in glTF-Transform's `textureCompress` does nothing for
  WebP.** It is a JPEG/AVIF option and sharp ignores it. The setting that
  addresses 4:2:0 chroma bleed is `smartSubsample`, which `textureCompress` does
  not expose at all — reaching it needs a direct sharp call.

- **`--keep-transparency` is a diagnostic, not a fix.** `<model-viewer>` has no
  order-independent transparency, so restoring BLEND on a multi-part garment
  trades one "half visible" for depth-sorting artefacts. Where alpha is
  implicated the answer is `MASK` with `alphaCutoff 0.5`.

- **`model-viewer.toDataURL()` returns a blank canvas.** three.js runs with
  `preserveDrawingBuffer: false`, so the readback is fully transparent (measured:
  all four channels zero). Screenshot the element instead.

- **The shrink container is not a workspace member**, so `pnpm -r typecheck`
  skipped it — the code that processes every real garment was never typechecked in
  CI. Now it is. It also cannot use `workspace:*` dependencies, because it is
  installed with plain `npm` inside Docker.

## The deploy that stopped itself — a mistake made *in this session*

The merge to `main` failed at the pre-deploy `migrate:remote` step:

```
TypeError: Cannot read properties of undefined (reading 'config')
  at .../apps/cms/src/migrations/replay.test.ts:33:1
```

**Cause, and it was mine.** Payload's `readMigrationFiles` reads the migration
directory and **dynamically imports every `.ts`/`.js` file in it except
`index.ts`**, treating each as a migration. The new replay test and its harness
had been put in that directory, so `payload migrate` imported the test file and
executed `describe()` with no vitest runner attached.

**What saved it.** The migrate step runs *before* the worker deploy, so its
failure stopped the release and the live site was never touched — the gated
design working exactly as designed, for the second time (see the 2026-07-22
incident above). Nothing was deployed, and nothing was broken.

**Fix.** Both files moved to `src/migrationReplay/`, and
`src/migrationReplay/migrations.test.ts` now asserts the migration directory
contains only files matching `<timestamp>_<name>.(ts|json)` plus `index.ts` — so
this cannot be repeated. It also checks every migration exports `up`/`down` and
that `index.ts` lists everything on disk.

**Lesson.** A directory that a framework globs is an API surface. Adding a file
to it is a behavioural change, not housekeeping. Local `pnpm test` passed
throughout, because vitest was perfectly happy to run a test file that Payload
was not — the two consumers of that directory disagreed and only one of them was
exercised before deploying.

## What was documented as done but did not exist

`SESSION-2026-07-29.md` records the fix for the data-loss incident as *"the
replay harness fails loudly if any child table ends up empty"*. **No such harness
was ever committed.** The incident could have recurred exactly as before.

It exists now, and it found two more latent bugs of the same class on its first
run. The lesson is not "someone forgot" — it is that a fix described in prose and
a fix that exists in the repo are different things, and only one of them runs.

Two other claims were found to be false and corrected in place:
`apps/cms/wrangler.jsonc` and `HARDENING-LOG.md` both asserted a working 14-day
R2 lifecycle rule on the ingest bucket. There is none; raw ~350 MB exports still
accumulate and bill indefinitely.

## What shipped

**Diagnostics.** `pipeline textures` / `render` / `compare`, plus
`tools/asset-pipeline/scripts/bisect-artwork.mjs`, which runs the production chain five times with one
stage removed each time and produces side-by-side contact sheets. Subtractive by
design: "which knob helps" had already been asked twice and produced a preset
that protects artwork *less* while looking better on the size chart.

**Artwork fixes.** Every UV set is weighted (H4); artwork textures get their own
encoder settings and `smartSubsample` is on everywhere (H5); transparency is
resolved per material from real alpha data, with cutouts becoming MASK and MASK
materials no longer double-sided (H6/H3).

**Instrumentation.** `simplifyTextured`'s counters were computed and shown to
nobody. They now reach the owner's report — the difference between "the flag did
not help" and "the flag never ran" was previously invisible.

**Backlog.** Migration replay harness; three migrations' down paths fixed; shrink
retries no longer orphan Media docs in the public bucket; two silent-failure
sinks closed; decoders self-hosted and asserted (gstatic gone from the CSP);
container typechecked in CI.
