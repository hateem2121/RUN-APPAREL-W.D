# Session 2026-08-04 — the Retry was ticked, and the gate caught the fix

**In plain words:** A diary of one work session: a safety check that stopped a bad file.

The previous session ended saying one checkbox was the highest-value action in the
project. It was ticked. **The pipeline refused to save**, and chasing that refusal
found the root cause of the damaged wordmark — a single mis-calibrated number that
explains *both* ways this bug has shipped.

Ten commits (`f78cf86` … `d8d745f`). 340 unit tests, up from 177 at the start of
the week.

---

## The gate did its job on its first real garment

The structural checks added the day before blocked five artwork materials left on
`alphaMode: BLEND` and saved nothing. That is the designed behaviour and it worked
— but the interesting part is *why* the fixed pipeline produced BLEND artwork at
all, one day after a session concluded the artwork path was fixed.

`solidifyMaterials` branches on `profileAlpha().character`. Measured on the live
`THE EXTRA MILE (Slogan)` texture, 1944×121 — the letters a customer photographed
as missing:

| | |
|---|---|
| transparent (`<=8`) | **66.38%** — the background around the letters |
| opaque (`>=248`) | **30.04%** — the letters |
| mid | **3.58%** — anti-aliasing on the letter edges |

**96.42% at the extremes, a cutout by any reading, and the 2% band missed it by
1.6 points.** Classified `graded`, it took the "genuine translucency, leave it on
BLEND" branch — a branch added *by* the 2026-07-31 artwork fix, to protect sheer
fabric.

What puts this texture over the line is **high ink coverage**, not thin strokes.
30% of the strip is ink, so there is a great deal of edge. An earlier draft of the
comment said "thin strokes have a high perimeter-to-area ratio"; a reviewer
rendered real wordmark type at this size across five faces and measured 1.2–2.3%
mid — already binary. Ordinary lettering was never affected. **The wrong
explanation is recorded here because it is the plausible one, and the next person
will reach for it.**

### Both ways of getting this wrong have now shipped to a paying customer

| | what `solidifyMaterials` did | what rendered |
|---|---|---|
| before `7bef9c4` (**the file live right now**) | forced `OPAQUE` | `OPAQUE` ignores the alpha channel, so the 66% transparent background painted its underlying RGB — measured **(240,240,240)**, a near-white box across the garment |
| after `7bef9c4` (this session's rerun) | left on `BLEND` | no OIT in `<model-viewer>` → half-visible; now correctly **blocked** |

The 2026-07-31 fix traded one bug for another, and nobody could see it because the
live file predates it by two days. **That is the same shape as the finding the
previous session led with** — "we fixed it" and "the fix is running" are different
claims — one level deeper.

## The fix is NOT simply a wider band

The first attempt raised `BINARY_MID_FRACTION` to 0.05. An adversarial review
refuted it before it shipped, with counterexamples that reproduce. They are tests
now.

- **A uniformly translucent inset** covering 2–6% of a map measures 1.95–6.06%
  mid, so it was swept up and MASKed at 0.5. Its alpha is ~0.35, so **every**
  fragment fails the alpha test: the region is not hardened, it is **deleted**,
  leaving a hole in the garment. Nothing downstream catches it — MASK at 0.5 is
  precisely what `findArtworkAlphaProblems` considers correct.
- **A material declaring `baseColorFactor[3] = 0.4`** plus a binary-looking
  texture became MASK/0.5 and rendered as nothing at all, silently, passing every
  gate.

So the shipped fix is a **pair**:

- `CUTOUT_MID_FRACTION` (0.05) governs *only* the BLEND→MASK decision in
  `solidifyMaterials`.
- `CUTOUT_MIN_TRANSPARENT` (0.05) — **a cutout must actually cut something out.**
  The wordmark is 66.38% fully transparent; every synthetic sheer inset measured
  0.000%, the feathered hem 0.098%.
- An explicit `baseColorFactor` alpha is tested **before** anything inferred from
  pixels.

`BINARY_MID_FRACTION` stays **0.02 deliberately**. `character` also feeds
`isArtworkTexture` → `findArtworkAlphaProblems`, which throws `PermanentJobError`
and saves nothing; widening it would widen a *blocking* gate for every texture in
the file, and buys this fix nothing anyway — at 16:1 the wordmark is already
artwork by `ARTWORK_ASPECT_RATIO`. **Keep destructive thresholds separate from
advisory ones.**

Each constant was verified load-bearing by reverting it alone and watching the
matching test fail.

## Two figures in the comments were wrong and are corrected, not dropped

`CLAUDE.md` makes these comments load-bearing, so a wrong one is a production risk
in its own right.

- "**two orders of magnitude**" of margin to genuine translucency. The repo's own
  ramp fixture measures 92.19% mid, not ~100%. **The real margin is ~26×.**
- "**nothing sits between** the extremes". Something does — 3.58% of the wordmark
  does, which is the entire bug. Now reads "almost nothing".

Both are stated as corrections rather than quietly edited, because the pattern of
*how* a comment came to overstate its case is worth as much as the number.

## Everything else that shipped

- **Colour names read from the file** (`variant-colour.ts`, `colour-name.ts`):
  dominant fabric by surface area, linear→sRGB, CIEDE2000 against a palette
  containing none of the observed hexes. Every published colour name on the live
  site was wrong; two colourways were never mapped at all.
- **The artwork gate** — three structural findings now throw `PermanentJobError`;
  the bytes-per-pixel measurement only warns, because a legitimately flat label
  encodes as small as a smashed wordmark.
- **CI made real**: gitleaks moved out of its own `security.yml` (where `needs:`
  could not reach it, so a commit carrying a live key scanned red and deployed
  anyway) into `ci.yml`. Four high advisories patched by override rather than
  suppression. The lockfile updated for the pinned pipeline dependencies.
- **e2e** now runs the browser a QR code actually opens — WebKit and mobile Safari
  — and the DOM suite no longer depends on the runner having a GPU.
- **Two dead buyer-facing routes** fixed: the wordmark no longer links nowhere,
  and `/n001` resolves to the default colour instead of the error page.

## State at end of session — read this before claiming anything is done

**The mechanism is measured. The render is not.** Nobody has yet zoomed in on a
re-processed logo. The whole point of `docs/OPEN-ISSUE-ARTWORK.md` is that
mechanism and appearance are different claims, and this session only settled the
first.

Specifically still open:

1. **Retry has not been ticked since the fix landed.** The live file is still the
   2026-07-29 near-white-box build. Raw upload #1 is still in the ingest bucket.
2. **1 of 5 artwork materials measured.** The gate named five; only
   `THE EXTRA MILE (Slogan)` was profiled.
3. **Newly-MASK'd materials are no longer double-sided by the pipeline.**
   Deliberate (H6: a decal has no inside, and its back faces z-fight), and
   `solidifyMaterials` never sets `false`, so a source-double-sided decal keeps
   it. But no test asserts sidedness on a material that *becomes* MASK inside the
   same call, and a CLO decal with inward normals would now render as nothing.
4. **The calibrating measurement is not reproducible from the repo.** The 364 MB
   raw export is in R2 only; the wordmark fixture in `pipeline.test.ts` is a
   synthetic approximation of the real proportions.
5. **"Re-upload at Highest quality" is still the advice** in three places for a
   failure it cannot fix. Detail controls decimation; this was an `alphaMode`
   decision made identically at every Detail level.
