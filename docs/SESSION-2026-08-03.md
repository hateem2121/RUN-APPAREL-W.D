# Session 2026-08-03 — production audit, then closing what it found

A full production-readiness audit, followed by implementing the plan it produced.
Unlike previous sessions this one started by **querying the live platform** rather
than reading the repo: Cloudflare Workers/D1/R2, the public API, and the live site
in a real browser. Most of what follows was invisible from the code.

---

## What the live site was actually doing

`https://viewer.wear-run.help/n001/navy` served, to a real buyer:

| The page said | What appeared |
|---|---|
| "Velocity Performance **Tee**" | a women's cycling skinsuit |
| "COLOURWAY 01 / **NAVY**" | a **maroon** garment |
| "COLOURWAY 02 / **BLACK**" | a **pink** garment |

and the chest wordmark, which should read `✳ THE EXTRA MILE`, rendered as
`⬛HE EXTRA ⬛⬛⬛⬛E`.

**The artwork damage is therefore confirmed** — the first time anyone had looked,
and `docs/OPEN-ISSUE-ARTWORK.md` was right that nobody had.

### The finding that reframes it

| | |
|---|---|
| Live GLB `cycling-all-colours-optimized-2.glb` built | 2026-07-29 14:34 UTC |
| Artwork fixes landed (commit `7bef9c4`) | 2026-07-31 16:37 UTC |

**The file on the site predates every fix by two days.** The damage seen is the
*old* damage; the fix has still never been exercised on a real garment. The raw
382 MB export is still in the ingest bucket (no lifecycle rule), and RawUploads
supports retry without re-upload — so one **Retry** tick both tests the fix and
replaces the damaged file. That remains the highest-value action in the project
and is not something this session could do.

## What was built

### Colour names are now read from the file

`tools/asset-pipeline/src/{colour-name,variant-colour}.ts`. Dominant fabric by
**surface area** (not material count — a garment cut into many small panels would
break that), excluding trim and artwork by name. `baseColorFactor` is linear per
the glTF spec and is converted to sRGB before naming; the match is **CIEDE2000**
in CIELAB, because RGB distance is perceptually non-uniform exactly in the dark
saturated region most sportswear occupies.

Measured against the five real colours, with a palette that deliberately contains
none of them (an earlier draft seeded it with the observed hexes and every ΔE came
out 0 — proving only that a lookup can find a value it was handed):

```
#502626 → Maroon        ΔE 6.32      #004D24 → Forest Green  ΔE 5.07
#E6AEAE → Blush         ΔE 2.29      #5B6666 → Slate         ΔE 1.50
#AEDCE6 → Powder Blue   ΔE 2.06
```

Surfaced as swatches in the "Which colour in your CLO file is this?" dropdown, so
mapping a maroon variant to a row named Navy is visibly wrong, plus an
`ImportColoursFromFile` action for variants with no row at all.

**Non-negotiable rules, each with its own test:** never write an existing slug
(printed on QR tags), never reorder rows (row order is the default colourway),
append only, arrive `active: false`, and leave the name blank rather than guess
when confidence is low.

### The artwork gate blocks

Three *structural* findings now throw `PermanentJobError` — artwork decimated
without UV protection (`artworkAtRisk`), artwork left `BLEND`, and a `MASK` whose
cutoff drifted off 0.5. Structural means a stated fact about the output with no
false-positive case, which is what makes them safe to block on.

The bytes-per-pixel check (`findCrushedArtwork`) only **warns**. It already
existed, with the right threshold, and was wired to nothing the automated path
called — the live damaged file trips it at 0.003 bpp against 0.02. It stays
advisory because a legitimately flat label encodes just as small as a smashed
wordmark.

A `Media.artworkVerdict` records the outcome, `assertPublishable` refuses a
`damaged` model, and an override requires a written reason.

### Everything else

Buyer-facing: the wordmark no longer links to a dead route; `/n001` resolves to the
default colour instead of the error page; a published product with no 3D file now
reports itself. Coverage: WebKit, mobile Safari and Firefox added — iOS Safari is
the primary QR target and had never executed a line of the suite. CI: gitleaks
moved into `ci.yml` so it can actually gate (in its own workflow it could only
fail its own run); the shrink container deploy gated on tests; the Docker build
made reproducible. Ops: a dead-letter consumer, a weekly diagnostics digest, and
`docs/BACKUP-RESTORE.md` now leads with D1 Time Travel.

## Traps found, all now in CLAUDE.md

1. **`opaque` defaults differently** between `parseOptimizeArgs` (true) and
   `optimizeGlb` (false). A hand-built options object skips the step that resolves
   a BLEND decal to a MASK cut-out. Found by an end-to-end test that "failed" and
   was blaming the pipeline for something only the test had done.
2. **React sets `src` as a property**, never an attribute, on a custom element.
   `getAttribute('src')` on `<model-viewer>` is always null.
3. **`webglcontextlost` is not composed** and never crosses the shadow boundary;
   model-viewer 4.x also renders into a shared *offscreen* canvas, so the one in
   the shadow root returns a `2d` context and `WEBGL_lose_context` on it does
   nothing. The real contract is model-viewer's `error` event with
   `detail.type === 'webglcontextlost'`.

## What was proposed and rejected

- **Adding `fileColours` to `GATED_FIELDS`.** This was in the session's own plan
  and is *wrong*: gating it once blocked the robot's recovery write on a
  published-but-model-less product. Built reporting instead
  (`becameUnverifiedWhilePublished`).
- **A per-job perceptual render check.** Chromium in the container against a
  $5/month cap, for a metric that would miss a 142 px wordmark band in a 2000 px
  frame anyway. The structural checks catch this class; a crop-targeted render
  check is the only version worth revisiting.
- **A "provably tears" fixture.** Cannot be built honestly without the render
  check. An end-to-end assertion that the guards *engage* on the real chain was
  built instead.

## Left unresolved, deliberately recorded

`VARIANT_NOTICE` in `Stage.tsx` is unreachable: `loadedSrcRef` is never truthy at
error time, so a mid-swap failure tears the stage down to a poster instead of
keeping the loaded model. The attribute-vs-property bug above was assumed to be
the cause; **an e2e test written to prove that failed**, so it is not. The cause
has not been isolated. The comment in `Stage.tsx` says so rather than implying a
fix that is not there.
