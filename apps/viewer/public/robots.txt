# Crawling is DELIBERATELY ALLOWED, and nothing here is disallowed.
#
# Every garment page is a link-preview target: apps/viewer/worker/index.ts rewrites
# per-garment Open Graph cards for crawlers, and the og:image it emits is
# /og/<product>/<colourway>.jpg on this same host. Facebook's and Twitter's crawlers
# honour robots.txt when fetching og:image, so a Disallow on /og/ would silently
# turn every shared link back into a generic card. That line was written and then
# removed on 2026-08-31 after checking what the Worker actually emits — it looked
# tidy and would have broken the feature.
#
# ⚠️ THIS FILE EXISTS TO STOP robots.txt BEING HTML. Until 2026-08-31 the build
# contained no robots.txt, so the Worker's SPA fallback answered /robots.txt with
# index.html: 9,853 bytes of `text/plain` holding 46 lines of markup, which a
# crawler parses line by line as directives.
#
# ⚠️ UNTIL 2026-09-04 THIS FILE WAS NOT WHAT WAS SERVED. Cloudflare's managed
# robots.txt prepended its own block to it, so the live file carried nine Disallow
# lines and a `Content-Signal: ai-train=no` that contradicted the first line above:
# Amazonbot, Applebot-Extended, Bytespider, CCBot, ClaudeBot, Google-Extended,
# GPTBot and meta-externalagent were all refused. Reading this file told you
# nothing about what a crawler received. The owner turned that feature off
# ("Disable robots.txt configuration") and separately set the deprecated "Block AI
# bots" rule to "Do not block" on 2026-09-04 — the second is load-bearing, because
# robots.txt only ASKS and that rule ENFORCED. Verified after both: 0 Disallow
# lines served, and GPTBot, ClaudeBot, Claude-User, OAI-SearchBot, PerplexityBot,
# Google-Extended, meta-externalagent and Googlebot each answered 200.
#
# So this file is now the whole story — which it was not before. If AI crawlers
# need blocking again, that is a dashboard decision, and this comment should be
# corrected in the same change.
User-agent: *
Allow: /
